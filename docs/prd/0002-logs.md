# PRD-0002: Logs: fields, creation, and the filtered list page

## 1. Summary

A log is one entry in a brag document: a thing you did, with its impact. Users add logs from the UI (and from Telegram, see [PRD-0003](0003-telegram-bot.md)) and browse them on a list page that filters by every field.

## 2. Problem

The article's core advice is to write accomplishments down as they happen and to state their impact. Free text does not prompt for impact, cannot be filtered, and does not aggregate. Structured logs make the "what did I do in the last 6 months?" question answerable in seconds.

## 3. Goals

- Adding a log takes under 30 seconds from the UI.
- A user can find any log from a year of entries with at most two filters.
- The fields nudge the user toward the article's guidance: impact first, evidence linked, fuzzy work tagged.

## 4. Non-goals

- Rich text or attachments in v1. Description is plain text with Markdown rendering.
- Comments or reactions on logs.
- Automatic import from GitHub, Jira, or calendars.

## 5. Users and personas

- **Author**: the document owner or an editor adding and maintaining logs.
- **Reader**: a viewer (manager or peer) browsing logs.

## 6. User stories

- As an author, I want to capture a win in one short form so that I do not postpone writing it.
- As an author, I want to attach links to the PR, doc, or dashboard so that the claim has evidence.
- As an author, I want to mark a log as `in progress` and later `done` so that the document is a living record.
- As a reader, I want to filter logs by tag, status, impact, and date so that I can prepare a review.
- As an author, I want to search by text so that I can find "that migration thing".

## 7. Functional requirements

| ID | Requirement | Priority |
|---|---|---|
| FR-1 | A log MUST belong to exactly one document. | Must |
| FR-2 | A log MUST have: **name** (required, ≤ 120 chars), **description** (optional, Markdown), **tags** (0..n, free text, lowercase), **reference links** (0..n URLs, each with optional label), **impact** (required, one of `low`, `medium`, `high`, `critical`, plus an optional free-text impact statement), **status** (`idea`, `in_progress`, `done`, `dropped`), and **created at** (set by the system, editable by the author to back-date). | Must |
| FR-3 | The create form MUST be reachable from any document page in one click. | Must |
| FR-4 | The author MUST be able to edit and delete their logs; editors MAY edit any log in the document ([PRD-0004](0004-sharing-and-rbac.md)). | Must |
| FR-5 | The list page MUST filter by: text (name + description), tags (any-of), status (multi), impact (multi), created-at range, and reference link domain. | Must |
| FR-6 | Filters MUST be combinable and reflected in the URL so that a filtered view can be bookmarked and shared. | Must |
| FR-7 | The list MUST sort by created at (default, newest first), name, impact, or status. | Must |
| FR-8 | The list MUST paginate or virtualize; 10,000 logs in a document MUST stay usable. | Must |
| FR-9 | Tags SHOULD autocomplete from tags already used in the tenant. | Should |
| FR-10 | The system SHOULD seed suggested tags from the article's sections: `project`, `collaboration`, `mentorship`, `design`, `documentation`, `company-building`, `learning`, `outside-of-work`. | Should |
| FR-11 | Every change to a log MUST be recorded with who and when (updated by, updated at). | Must |

## 8. Non-functional requirements

- NFR-1: List page p95 response under 300 ms for documents up to 10,000 logs.
- NFR-2: Filter results for a document MAY be cached for 60 s; a write to the document MUST invalidate the cache ([ADR-0006](../adr/0006-redis-as-cache.md)).
- NFR-3: Reference links are rendered with `rel="noopener noreferrer"` and never fetched server-side.
- NFR-4: Forms are keyboard-navigable and labelled for screen readers.

## 9. UX notes

- Create/edit log: a single form, name and impact on top, description next, tags and links below, status and date last. Submit with Cmd/Ctrl+Enter.
- List page: filter bar on top, active filters shown as removable chips, result count, table or card rows with name, impact badge, status badge, tags, date.
- Empty state for a new document: three example logs written in the article's spirit, clearly marked as examples, deletable in one click.

## 10. Data

- **Log**: id, tenant, document, name, description, impact level, impact statement, status, created at, created by, updated at, updated by.
- **Tag**: name, tenant. Many-to-many with Log.
- **Reference link**: id, log, url, label.

## 11. Success metrics

- Median time from "New log" click to save under 30 s.
- 70 % of logs have at least one reference link.
- 90 % of logs have an impact statement.

## 13. Decisions log

| Date | Decision | Why |
|---|---|---|
| 2026-10-08 | Tags are free text, not a managed taxonomy | Matches the article's "fuzzy work" guidance; taxonomy can come later |
| 2026-10-08 | Impact is a fixed level plus a statement extracted by an LLM from the description ([PRD-0007](0007-impact-extraction.md)); no separate statement input | Keeps the form short; impact stays measurable |
| 2026-10-08 | NFR-2 cache deferred | Indexed queries are expected to meet NFR-1; add the cache when measured otherwise |
| 2026-10-08 | Owner-only until [PRD-0004](0004-sharing-and-rbac.md); archived documents are read-only | No grants exist yet |
| 2026-10-08 | Example logs are inserted when a document is created; existing documents get none | Matches §9 literally, one-click removal |
